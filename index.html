StarRocks / starrocks  ·  #73509
[BugFix] Fix FE startup failure during ADLS2 shared-data disaster recovery caused by AZURE_PATH_KEY validation
Merged
// the bug

During Azure Data Lake Storage Gen2 (ADLS2) cluster snapshot disaster recovery, the restoration process injects AZURE_PATH_KEY into storage volume parameters. This constant was not registered in CloudConfigurationConstants.PARAM_NAMES, causing StorageVolumeMgr.validateParams() to throw a DdlException and completely abort FE (Frontend) node startup — blocking all disaster recovery completion.

// the fix
// Before: AZURE_PATH_KEY lived in AzureCloudConfigurationProvider // invisible to the shared validation system - private static final String AZURE_PATH_KEY = "azure_path";   // After: moved to CloudConfigurationConstants (shared module) // reflection-based validateParams() can now discover it + public static final String AZURE_PATH_KEY = "azure_path";
// impact
Root Cause
Cross-module constant visibility gap in shared credential config
Outcome
FE nodes now start successfully after ADLS2 DR restoration
Backport
Cherry-picked to branch-4.1 for older release users
